# ADR-003

## Title

Protect Domain Invariants Through Encapsulation

## Status

Accepted

---

## Context

При проектировании сущности User возник вопрос:

Следует ли разрешить изменять свойства напрямую?

Например:

```csharp
user.Email = "...";
```

или

использовать методы:

```csharp
user.ChangeEmail(...);
```

Необходимо определить,
кто отвечает за защиту бизнес-правил.

---

## Decision

Сущности Domain не должны позволять
произвольное изменение своего состояния.

Все изменения должны происходить
через методы,
выражающие бизнес-действия.

Например:

- ChangeEmail()
- ChangePassword()
- Block()
- Unblock()
- AssignRole()

Поля должны иметь

```csharp
private set;
```

или быть полностью неизменяемыми,
если это возможно.

---

## Consequences

### Плюсы

- инварианты защищаются самой Domain;
- невозможно обойти бизнес-правила случайным присваиванием;
- поведение становится явным;
- код лучше отражает предметную область;
- снижается вероятность появления неконсистентного состояния.

### Минусы

- немного больше кода;
- необходимо проектировать методы,
а не только свойства.

---

## Notes

Важно различать ответственность слоёв.

### Domain

Защищает локальные инварианты.

Например:

- нельзя заблокировать уже заблокированного пользователя;
- имя не может стать пустым;
- роль всегда существует.

### Application

Координирует операции,
требующие внешних данных.

Например:

- проверка уникальности email;
- загрузка пользователя из БД;
- работа с другими сервисами.

### Infrastructure

Реализует технические детали:

- EF Core;
- PostgreSQL;
- SMTP;
- JWT;
- файловая система.
